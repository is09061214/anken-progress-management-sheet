Chapter 1

全体アーキテクチャ

データの源泉は1つ（Google スプレッドシート）。届け方は3ルート。判定ロジック（app/signal.py）は Web も Discord も同じコードを共有するので、表示と通知がズレません。

📋
Google スプレッドシート「iMuseLLC 案件管理表」

チーム全員が普段更新。ダッシュボードは読み取り専用。

↓
⚙️ 共通処理コア（Python app/）
  • sheets.py — 取得・日付パース・ヘッダー検証
  • signal.py — 赤黄青灰の判定
  • config.py — 列番号・閾値・JST
↓ 同じ判定結果を3ルートで配信 ↓
🌐 ルート A — Web ダッシュボード
  1. FastAPI が起動時＋60分ごとに取得
  2. VideoStore がメモリにキャッシュ
  3. Jinja2 で HTML 生成
  4. Cloud Run 等で常時公開

GET / · POST /refresh · GET /healthz

💬 ルート B — Discord 朝の進捗通知
  1. GitHub Actions が毎朝 cron 実行
  2. discord_notify.py が同じ app を import
  3. Pillow で 1200×630 サマリ画像
  4. Webhook に画像＋挨拶＋格言を POST

discord_morning.yml（JST 6:30前後）

🎬 ルート C — 撮影予定 月曜朝通知
  1. 毎週月曜、Google カレンダーから今後14日間の「撮影」イベント取得
  2. film_notify.py が Discord に撮影予定を通知

進捗信号とは別系統。同じ Discord / GitHub Actions 基盤。

Chapter 2

データパイプライン

シートの1行が、どうやってダッシュボードの1行になるか。

Step 1

🔐 サービスアカウントで Sheets API に接続

ローカルは JSON ファイル、GitHub Actions は Secrets の JSON 文字列を一時ファイル化、Cloud Run は ADC。

Step 2

📑 WORKSHEET_GID で正しいタブを選択

不一致時は例外（先頭タブへの自動フォールバックは既定 OFF）。誤シート読み込み事故を防ぐ。

Step 3

✅ 行2のヘッダーをキーワードで検証

「クライアント」「動画」「状況」「投稿」等。列構成変更に即気づける。

Step 4

🧹 ノイズ行を除外

「未入力」「未撮影」「未定」等のプレースホルダ、公開済み（完了/済）、空行をスキップ。

Step 5

📅 年なし日付を JST 基準で年補完

5/10 形式も infer_year() で最も妥当な年を推定。

Step 6

🚦 D列 × F列 → 赤黄青灰

たった2列だけ。ガント列（I以降）は使わない。

Step 7

📊 赤・黄を優先表示、灰は折りたたみ

ソート: 赤→黄→灰→青。モバイルはカード、PCはテーブル。
